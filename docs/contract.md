# Contract — development 0.1.0

This contract describes a deliberately narrow geometry/document model. It is not a physical loading or engineering standard.

## Coordinates and arithmetic

All authoritative coordinates are safe integer millimetres. X is width, Y is up, Z is depth. A position is the nonnegative minimum corner **after orientation**, not a pivot or centre. Container and base box dimensions are each 1–12000 inclusive. Positions are 0–12000; full bounds checks impose tighter limits. There are at most 200 boxes.

An orientation is a row-major 3×3 signed integer matrix from the 24 right-handed axis-aligned rotations. Each row and column has one nonzero ±1 entry and determinant +1. Identity is `[1,0,0,0,1,0,0,0,1]`. The exported `ORIENTATIONS` list is deterministic, starting with identity and generated by X/Y/Z breadth-first quarter turns.

Positive world-axis quarter turns pre-multiply the existing orientation:

- X: `[1,0,0, 0,0,-1, 0,1,0]`
- Y: `[0,0,1, 0,1,0, -1,0,0]`
- Z: `[0,-1,0, 1,0,0, 0,0,1]`

There is no authoritative trigonometry. Negative zero is normalized. Oriented extents are `abs(R) * baseSize`. Rotation retains the exact minimum position. Rendering places base-size geometry at `position + extent/2`, rotated by R.

A box is inside iff `position[i] + extent[i] <= container[i]` on every axis. Contact at the boundary is legal. Two boxes conflict iff their interiors overlap positively on **all three** axes. Face, edge and corner contact is legal. `Three.Box3.intersectsBox` is not used to authorize placement because it includes contact.

All products and sums are exact within JavaScript safe integers: even `200 * 12000^3 = 345600000000000 < 2^53`. Occupied volume is the sum of base volumes after collision validation. Display percentage alone is rounded to one decimal; no rounded values authorize geometry.

## JSON schema

The only root fields, in canonical order, are `version`, `unit`, `container`, `boxes`. Version is the number `1`, unit is the string `mm`. A minimal useful document is:

```json
{
  "version": 1,
  "unit": "mm",
  "container": [1000, 1000, 1000],
  "boxes": [
    {
      "id": "a",
      "label": "Synthetic cube",
      "size": [100, 100, 100],
      "position": [0, 0, 0],
      "orientation": [1, 0, 0, 0, 1, 0, 0, 0, 1]
    }
  ]
}
```

Each box has exactly the five displayed fields. `size` is base size, not oriented extents. All vectors have exactly three numeric elements; orientation has exactly nine. Nulls, booleans, numeric strings, fractions, unsafe integers, infinities, sparse arrays, unknown keys and absent fields are rejected. Empty `boxes` is valid.

IDs are unique and match `[A-Za-z0-9_-]{1,64}`. This is an intentionally restricted ASCII grammar. `__proto__` and `constructor` are valid IDs: IDs are compared with sets and values, never used as prototype-bearing dictionary assignments. Labels may be empty; they must be well-formed Unicode, at most 128 UTF-8 bytes, without NUL. Labels do not execute as HTML.

Text imports are limited to 262144 UTF-8 bytes **before any JSON token decoding**. A cheap UTF-16 length rejection precedes UTF-8 encoding. Browser files are size-checked before `file.text()` and text is independently bounded afterward. A strict bounded recursive JSON grammar rejects duplicate object members, including escaped-equivalent keys, invalid syntax, trailing tokens and nesting deeper than sixteen. Whitespace is JSON space/tab/CR/LF; a BOM is not accepted. Schema, matrix membership, caps, IDs, bounds and collisions are all validated before replacement. This is not a pre-decoder recursion or RSS sandbox; byte bounding and depth checks do not provide process isolation.

Canonical export contains only accepted data. Properties have the order shown above. Boxes sort by ASCII code-unit comparison (`<`/`>`), never locale comparison. Export is `JSON.stringify(document, null, 2)` followed by one LF, with no locale, selection, camera, history, timestamps or derived metrics. Import property order is immaterial.

## Public core API

`validate(unknown): Document` captures own enumerable data descriptors, copies vectors and boxes, normalizes values and deeply freezes accepted data. Plain objects with Object/null prototypes and ordinary arrays are supported. Accessors, custom prototypes, array holes, extra array keys and custom iterator properties are rejected without invoking their getters/iterators. Arbitrary Proxies can execute traps in JavaScript reflection: they are **not** sandboxed. Prefer text import for untrusted input.

`createSession(acceptedDocument?)` creates an opaque, frozen session. Omitting the document uses the synthetic demo. `change(session, candidate)` validates a complete candidate before creating a new session. A rejected command throws `Fault` and does not return a replacement. An equal canonical edit is a no-op: it returns the original session with no undo entry. Four successful quarter turns are four commands, even if dimensions are equal; after four turns the document bytes are restored, not the prior history.

`rotate(session, id, 'X'|'Y'|'Z')` applies the matrices above and validates the whole candidate. `importText(session, text)` makes exactly one undoable replacement for every valid import, including an identical document. `undo(session)` restores the previous accepted document exactly; empty-history undo is a no-op. History retains the last twenty successful non-no-op commands. There is no redo.

Sessions and export functions require objects actually returned by this module, rather than structurally forged accepted documents. `toJSON`, `volume`, `containerVolume`, and `toSVG` export only accepted documents. Low-level `multiply`, `extents`, `overlaps` and `conflictPairs` are typed geometry helpers for trusted bounded operands, not independent untrusted-input validators.

`Fault` exposes a stable `code`, a diagnostic `field`, and textual `details` such as IDs. Code categories are `type`, `keys`, `accessor`, `range`, `id`, `label`, `orientation`, `bounds`, `overlap`, `duplicate`, `count`, `schema`, `bytes`, `json`, `duplicateKey`, `depth`, `document`. The UI adds `number` for numeric drafts and `io` for file failures. Error messages are localized outside the core. Invalid API usage involving Proxies may throw native errors; the UI catches unexpected failures without committing them.

The UI creates complete candidates for add, remove, move, base resize and container resize. Selection, camera, locale and drafts are UI-only. Rejected edits preserve selection and accepted state/history. Successful removal/import selects the first ASCII-sorted box if the old ID no longer exists. Selecting/camera/locale/export never adds history. Successful accepted changes refresh drafts; an unapplied draft is not an export. Rotation buttons operate on the accepted box, not unapplied numerical drafts.

## SVG and browser I/O

`toSVG` emits a standalone UTF-8 document with XY, XZ and ZY orthographic views. Projection coordinates derive only from the accepted geometry. Positive vertical coordinates display upward. Labels and IDs are XML-escaped inside titles. The file contains no scripts, `foreignObject`, event handlers, imported URLs, fonts or models. The XML namespace is structural, not a resource fetch. Font fallback uses local viewer fonts. The occupancy header is bilingual and locale-independent.

Browser exports use a Blob, temporary anchor and object URL, then remove the anchor and revoke the URL. Download failure is shown without altering geometry. Tests inject an explicit download adapter; that does not prove a real browser download. File read failures and oversize files preserve the last accepted document. A newer explicit geometry/import/undo command revokes an older asynchronous file read, so the older result cannot overwrite newer intent. Camera navigation is explicit and has an end button/Escape exit; it never changes geometry or history. No state persists implicitly across reloads.

## Deterministic default

Container: `[6000,2400,2400]`. Six boxes, each `[1000,800,800]`, identity orientation, IDs `box-001` through `box-006`, labels `B01` through `B06`, positions:

```text
[0,0,0]
[1000,0,0]
[2000,0,0]
[0,0,800]
[1000,0,800]
[0,800,0]
```

Occupied volume: 3840000000 mm³. Container: 34560000000 mm³. Fraction: 1/9. Rounded percentage: 11.1% (11,1% in the Portuguese interface). The fixtures have no industry container/load certification. No support, gravity, weight or optimal-packing inference is valid.

### New-box draft suggestions

The UI adapter tries at most `1 + 3n` origin/positive-face candidates, deduplicated and sorted by Y, then Z, then X. It clamps initial dimensions to the container, rejects bounds/overlap candidates, and validates the complete proposed document before returning a suggestion. A missing suggestion is not a proof of insufficient free volume. A complete valid draft has a separate non-selectable translucent/dashed preview; an invalid draft has only a diagnostic. Neither enters the accepted document, statistics, exported JSON/SVG or history. Apply validates authoritatively and adds one command; Cancel discards only the draft. Starting or editing a draft revokes a pending older file import. This heuristic is not packing optimization.
